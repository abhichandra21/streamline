Help

Everything you need to know about using Streamline.

How it works

Streamline is a two-phase recommendation engine built on your real watch history.

Setup (offline) — Parses your Netflix, Prime Video, and manual watch history. Fetches metadata from TMDB, enriches each title with a semantic description, then builds a detailed taste profile from everything you've watched.

Search (online) — Ask anything in natural language. The engine parses your intent, finds candidates via TMDB Discover + AI semantic suggestions, filters out what you've seen, checks streaming availability, and ranks results against your taste profile.

Query guide

This is the canonical guide to what you can ask Streamline. These examples match the current code paths.

Standard recommendation queries

  • Genre + mood — "gritty British crime drama", "feel-good Bollywood comedy"
  • Similar to — "spy thriller like Slow Horses", "something like Fleabag but darker"
  • Runtime + count — "give me 5 underrated sci-fi movies", "90-minute thriller", "short documentary series"
  • Language/region — "Hindi crime thriller", "Korean romance", "French arthouse"
  • Platform — "what's good on Netflix right now", "best Prime Video originals", "Apple TV+ sci-fi"

Special query modes

  • Why not? — "why not Slow Horses?" explains why a title was filtered out or never surfaced.
  • Abandoned-watch advice — "I started Severance and stopped. Should I keep going?" or "I dropped The Boys after a few episodes. Worth finishing?"

Interactive refinements in ./recommend

  • More options — "what else?" or "anything else?" reruns the last query without repeating prior results.
  • Pick from a prior result — "more like #2" uses the second result from the previous turn as the new anchor title.
  • Refine the last request — "but something British", "something lighter", "make it a movie".

Command-style inputs are not recommendation queries.

  • +liked Title, +disliked Title, +add Title tv|movie work inside interactive mode.
  • ./recommend --liked "Title", --disliked, --add, and --history are CLI commands.

Runtime note — ordinary recommendations run from the cached watch index and taste profile after setup. Abandoned-watch queries depend on raw watch events, so they are less useful if your provider zips are no longer available at runtime.

Results show the title, TMDB rating, genres, a personalized explanation of why it matches your taste, and where it's streaming.

Taste profile

Your taste profile is built from all titles in your watch history, processed in batches and merged into clusters. Each cluster captures a distinct pattern in what you watch — genre preferences, tonal signatures, cultural interests.

The profile is rebuilt when you run setup with --refresh-profile. It automatically backs up the previous version.

Feedback (liked/disliked titles) influences the profile on the next rebuild — liked titles get a score boost, disliked titles are noted as patterns to avoid.

CLI commands

Everything goes through ./recommend:

./recommend "query"Single query
./recommendInteractive mode with refinements like "what else?", "more like #2", and follow-up edits
./recommend setupFirst-time offline setup
./recommend setup --refresh-dataRe-fetch TMDB metadata + rebuild everything
./recommend setup --refresh-profileRebuild taste profile only
./recommend --historyShow recent query history
./recommend --debug "query"Full pipeline trace
./recommend -n 5 "query"Override result count
./recommend --provider gemini "query"Use Gemini instead of default
./recommend --liked "Title"Mark a title as liked
./recommend --disliked "Title"Mark a title as disliked
./recommend --add "Title" --type tvAdd to watch history

Inside interactive mode, you can also type +liked Title, +disliked Title, or +add Title tv|movie.

Web server:

./recommend-web startStart web UI (default port 5050)
./recommend-web stopStop the server
./recommend-web restartRestart
./recommend-web statusCheck if running
./recommend-web logsView recent logs
Configuration

Settings live in a few places:

  • Environment variables — API keys only (TMDB_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY, OPENAI_API_KEY).
  • .env — optional local convenience for setting those variables. Gitignored.
  • config.yaml — shared repo defaults and app settings. Editable from the Settings page or by hand.
  • config.local.yaml — local overrides such as watch-history zip paths. Gitignored and loaded after config.yaml.

Provider API keys use the standard variable names by default. Only set api_key_env when you need a custom variable name.

The Settings page lets you change provider, models, timeouts, scoring weights, and more — changes take effect immediately without a restart.

Title overrides

When TMDB can't match a title from your watch history, create data/overrides.json:

{
  "The Matrix III Revolutions": {"title": "The Matrix Revolutions"},
  "Some Cooking Show Ep 3": {"skip": true},
  "Delhi Cops Episode": {"title": "Delhi Cops", "content_type": "tv"},
  "Specific Movie": {"tmdb_id": 12345}
}

Options: title (search name), content_type (tv/movie), tmdb_id (direct match), skip (exclude entirely). The override file is auto-detected — just run ./recommend setup.

Adding watch history

Set each provider path in config.local.yaml to the exact raw export zip file. Start from config.local.example.yaml:

NetflixAccount Settings > Download your data > Netflix export zip
Prime VideoAccount > Digital content > Request your data > Prime Video export zip
Apple TVApple privacy export > Apple Media Services Information Part 1 of 2.zip
Manualdata/manual/tv.csv and data/manual/movies.csv — one title per line

Run ./recommend setup --ingest-only to validate the configured provider zips before rebuilding.

After adding new data, run ./recommend setup --refresh-data to rebuild.

You can also add individual titles via CLI: ./recommend --add "Shetland" --type tv

LLM providers

Streamline supports two LLM providers. Each uses two model roles:

  • Fast — used for enrichment (high volume, simple task). Default: Haiku / Flash.
  • Reason — used for intent parsing, ranking, taste profile (complex reasoning). Default: Sonnet / Pro.

Switch providers in Settings or per-query with --provider gemini. Token usage and cost estimates are shown after each query.
